# وثيقة المشروع الشاملة — برنامج ماستر

> وثيقة تلخّص كل ما أُنجز حتى الإصدار 0.13.0 (17/10/2026). المرجع التفصيلي للقواعد هو [`docs/10-spec`](../10-spec/README.md) و[سجل القرارات B001–B094](../40-decisions/B001-B094.md) و[فهرس القرارات](../40-decisions/INDEX.md)؛ هذه الوثيقة خريطة ترشدك إليها ولا تغيّر أي قاعدة.

## 1. التعريف والنطاق

- **ماستر**: نظام موحد للمبيعات والمرتجعات والتحصيلات والذمم والأهداف والعمولات والخرائط والتقارير، بواجهة عربية من اليمين لليسار.
- **خارج النطاق**: الرواتب. وبيانات العملاء الفعلية لا تُرفع إلى المستودع (DATA-011: المبالغ شاملة الضريبة، ولا ضريبة تُضاف في النظام).
- **المنصة المعتمدة**: Google AI Studio (نشر الواجهة) + Supabase (قاعدة البيانات والمصادقة).
- **مستودع العمل**: `mqtashat/MASTER---V2`. المستودع `MASTER-system` للقراءة والمقارنة فقط ولا يُعدَّل.

## 2. القواعد الثابتة للعمل

1. لا تُخترع قاعدة تجارية أو مالية أو قيمة افتراضية؛ ما لم يُنص عليه يُسأل عنه أو يُضاف إلى [الأسئلة المفتوحة](../50-open/OPEN-QUESTIONS.md).
2. لا تُعاد فتح القرارات المعتمدة.
3. كل تعديل في فرع مع commit واضح ثم طلب دمج (PR) للمراجعة قبل الدمج.
4. قبل كل push تنجح الأداتان: `python3 tools/check_links.py` و`python3 tools/verify_coverage.py`.
5. الردود بالعربية الفصحى مختصرة ومرتبة.
6. لا بيانات عملاء حقيقية في المستودع.
7. ترتيب الأولوية عند التعارض: جولة الاعتماد الأحدث ← بنود B001–B094 ← نص ملف المجال.

## 3. البنية التقنية

| الطبقة | التقنية | الموضع |
|---|---|---|
| الواجهة | React 18 + TypeScript + Vite، HashRouter، RTL، `supabase-js`، Leaflet للخرائط | `app/` |
| قاعدة البيانات | PostgreSQL على Supabase: دوال `security definer` عبر PostgREST (RPC)، وأمان الصفوف RLS، ومفتاح anon فقط في التطبيق | `supabase/` |
| الاختبارات | اختبارات قاعدة البيانات (125)، اختبارات المتصفح بـPlaywright للوحدات 1–7، واختبارات الواجهة بـvitest (7)، واختبارات الحمل | `tests/` و`app/` |
| المرجع | قواعد وقرارات وتجربة استخدام وحالات قبول | `docs/` |
| الأدوات | فحص الروابط والتحقق من اكتمال النقل | `tools/` |

مبادئ ثابتة:
- لا كتابة مباشرة على الجداول؛ الكتابة عبر دوال محمية بصلاحية ونطاق بيانات.
- الصلاحيات حسب الصفحة (P01–P21) ونطاق البيانات (الكل / الفريق / الشخصي)؛ الرمز السري للإدارة (AUTH-004) لفتح الأشهر المقفلة والتعديل المطلق ومحفوظ مُجزّأً.
- الحسابات تُنشأ من داخل النظام باسم مستخدم وكلمة مرور (B074).

## 4. طريقة التسليم والتعديل

- **البناء الأول (BASE-007)**: البناء والاختبار محليًا، ثم تسليم ملف ZIP إلى AI Studio وربطه بـSupabase. التطبيق منشور اليوم على AI Studio.
- **التعديل بعد النشر (BASE-008)**: يُطبَّق كل تعديل في AI Studio ببرومت ويتحقق منه المستخدم، ثم يُوثَّق ويُنفَّذ ويُختبر في المستودع بطلب دمج. تعديلات SQL يشغّلها المستخدم في Supabase SQL Editor بالترتيب.
- **تطبيق قاعدة البيانات**: مشروع جديد يأخذ `supabase/schema.sql` (مجمّع بالأمر `bash supabase/build_schema.sh`)، ومشروع قائم يشغّل ملف الترحيل الجديد وحده. ملفات 0012–0014 قابلة لإعادة التشغيل ومحصنة ضد نهايات الأسطر CRLF عند اللصق.
- **الحزم**: `bash app/make_zip.sh` ينتج `dist-zip/master-app.zip`، و`dist-zip/0012_to_0014.sql` حزمة ترحيلات الدفعة الأخيرة، و`dist-zip/ai-studio-prompt-0.13.0.md` برومت التطبيق.

## 6. القواعد الأساسية (ملخص)

### البيانات والرفع
- مفتاح السند ثابت، والتحديث باستبدال السند كاملًا بعد المعاينة دون دمج تخميني (DATA-003/004، B046).
- السند المعلّق لا يدخل الحسابات حتى يُصحَّح أو يُستبعد؛ الموظف غير المعرّف يمنع اعتماد السند حتى يُعرَّف (DATA-010).
- أنواع الفاتورة: «فاتورة نقدي» و«فاتورة ذمم» فقط (INV-011).

### الحسابات
- ترتيب الحساب (FIN-001): الافتتاحيات المدينة ثم الأقدم فالأحدث؛ التحصيل الزائد رصيد دائن يسدد الديون اللاحقة ولا يُصرف نقدًا (STMT-009).
- سياسة توزيع لكل عميل بتاريخ سريان؛ ديون الحساب الرئيسي تدخل افتراضيًا (ALLOC-002).
- المرتجع مؤثر إن كان الرصيد قبله دائنًا وإلا نقدي، ويُعلَّق إن كان الافتتاح غير معلوم (RET-005/010).
- إغلاق السنة يرحّل الأرصدة ويعرض الفروق دون استبدال صامت.

### الأهداف
- الهدف النهائي = B × (E − P) ÷ E بحسب أيام العمل، والشهر الجزئي متناسب أو ثابت، وأهداف الأعداد تُقرَّب للأعلى (GOAL-004..011).
- شرائح A وB وC بترتيب محفوظ، بشرط AND/OR، وX للشريحة غير المستخدمة. **ترتيب الشرائح** للمقياس نفسه بفلاتره نفسها A ≥ B ≥ C ويمنع الحفظ (GOAL-018).
- هدف المشرف مجموع فريقه أو مستقل، ويحترم فلاتر المكوّن.
- **الجدول الجماعي**: هيكل واحد للشهر يُعمَّم على الكل أو البعض بمعاينة (جديد / متغير / بلا تغيير / خطأ) واعتماد كله أو لا شيء (GOAL-019).
- مقاييس متخصصة: التغطية %، نسبة التنوع % (بقائمة أصناف إلزامية)، هدف التحصيل بأساس يُختار في كل هدف.

### العمولات
- قاعدة واحدة للموظف في الشهر؛ نسبة الشريحة (المندوب بالمئة والمشرف بالألف) أو نسبة الصنف بتاريخ السند؛ غياب القاعدة أو النسبة يجعل الكشف غير مكتمل (COMM-007).
- المبلغ المؤهل: صافي المبيعات، وللمشرف مبيعاته الشخصية صافية المرتجعات بالإضافة لحصة الفريق (COMM-003/005/006).
- عمولة التحصيل لمندوبين تختارهم الإدارة، على المسدد ضمن المهلة، بشريحة شهر الفاتورة (COMM-008).
- الإضافات الجديدة:
  - استثناء موظف داخل القاعدة: حد أدنى للمبيعات (دونه الأساسية صفر فقط) أو نسبة يدوية (COMM-009).
  - القاعدة التصاعدية: إضافة على كل المبيعات المؤهلة عند تجاوز عتبة بخطوة وسقف (COMM-010).
  - مكافأة التنويع: مجموعات أصناف عامة (PRD-009) ومستويات بحصص تضيف نسبة إلى نسبة الشريحة (COMM-011).
  - إلغاء كل قرارات الشهر المفتوح دفعة واحدة بسبب ومعاينة (COMM-012).
- المستحق النهائي لثلاث منازل (B062).

### المكافآت
- بالجمع أو الأعلى فقط (B023)، وتُصرف بترتيب B024 والنسبة بأساس صريح (B025).
- مكافأة تجاوز هدف A الأصلي بمستويات (مبلغ أو نسبة) على صافي المبيعات، وتُصرف لأعلى مستوى (REWARD-003).
- سريان المكافأة لأكثر من شهر مع تقييم كل شهر منفردًا (REWARD-004).

### الإغلاق والأشهر
- الإغلاق يتطلب فحص جاهزية بلا أخطاء مانعة، ويحفظ نسخة لكل كشف وبطاقة وإعدادات الشهر؛ إعادة الفتح برمز الإدارة وسبب، ويُنشأ إصدار جديد (PERIOD-001/002).
- الشهر المغلق يُقرأ دائمًا من نسخته الحالية.

### الخرائط
- موقع العميل صالح / مفقود / غير صالح (0،0 غير صالح)، والمناطق بنسخ مؤرخة، والعميل في منطقتين يحتاج تحديد منطقة.
- مزود الخرائط المعتمد Google Maps (MAP-013)، ويعمل مؤقتًا على OpenStreetMap عبر Leaflet حتى يُضبط المفتاح.

### الخصوصية والنطاق
- المستخدم لا يرى ولا يعدّل خارج نطاقه (B072، AUTH-002)؛ أسماء من خارج النطاق تُخفى مع بقاء العدد؛ إجماليات الشركة ونسخ الإغلاق للنطاق الكامل فقط.

## 9. ما بقي مفتوحًا

**قرارات تنتظر المستخدم**
- OQ-04: ملفات تاريخية حقيقية لمطابقة النظام قبل التشغيل.
- OQ-09: عند استيراد مواقع بإحداثيات معكوسة، هل يبدّل النظام تلقائيًا أم يكتفي بالتنبيه (المعمول به الآن التنبيه).
- أسئلة التدقيق السبعة (الحالة الحالية لكل منها في ما تفعله الشيفرة اليوم، ولم يُغيَّر شيء بانتظار قرارك):

| # | الموضوع | السلوك الحالي |
|---|---|---|
| Q-أ | رؤية المشرف لمندوب انتقل من فريقه | يرى بياناته قبل الانتقال وبعده |
| Q-ب | شريحة المكافأة في البطاقة مقابل الكشف | البطاقة تتبع المحسوبة والكشف اليدوية |
| Q-ج | عمولة تحصيل الرصيد الافتتاحي | بشريحة شهر السداد، للمندوب فقط، بلا حد عمر |
| Q-د | موظف بلا قاعدة ولا مبيعات | يمنع الإغلاق |
| Q-هـ | ترتيب الإغلاق وتوقيته | يمكن إغلاق الشهر الحالي قبل نهايته وبغير ترتيب |
| Q-و | العميل «الجديد» لمندوبين في الشهر نفسه | جديد لكليهما |
| Q-ز | موظف بلا أيام عمل | يأخذ الهدف الأصلي كاملًا |
