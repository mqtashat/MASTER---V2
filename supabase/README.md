# قاعدة بيانات ماستر على Supabase

## الملفات

- `migrations/` ملفات الترحيل بالترتيب: `0001_foundation.sql` ثم `0002_users_settings.sql` ثم `0003_definitions.sql` ثم `0004_transactions.sql` (الرفع الموحد والسندات) ثم `0005_accounts.sql` (الحسابات والكشف) ثم `0006_goals_commissions.sql` (التقويم والأهداف والعمولات والمكافآت والإغلاق) …
- `schema.sql` ملف واحد مجمّع من الترحيلات بالترتيب نفسه، يُولَّد بالأمر `bash supabase/build_schema.sh` لتطبيقه دفعة واحدة.

## التطبيق على مشروع Supabase جديد

1. أنشئ مشروعًا في Supabase.
2. افتح **SQL Editor** ثم الصق محتوى `supabase/schema.sql` كاملًا وشغّله مرة واحدة.
3. من **Project Settings → API** انسخ:
   - **Project URL**
   - **anon public key** (المفتاح العام فقط؛ لا يوضع مفتاح service_role في التطبيق إطلاقًا).
4. افتح التطبيق؛ تظهر شاشة الاتصال عند أول فتح، أدخل فيها العنوان والمفتاح العام. أو اضبطهما متغيري بيئة:
   `VITE_SUPABASE_URL` و`VITE_SUPABASE_ANON_KEY`.
5. تظهر شاشة **تهيئة النظام** مرة واحدة لإنشاء حساب الإدارة الأول.

## ملاحظات أمنية

- كل جدول عليه أمان الصفوف (RLS): القراءة بالصلاحية ونطاق البيانات، ولا كتابة مباشرة على الجداول؛ الكتابة عبر دوال محمية فقط.
- الحسابات تُنشأ من صفحة «المستخدمون والصلاحيات» باسم مستخدم وكلمة مرور (B074). يُفضَّل تعطيل التسجيل الذاتي في
  **Authentication → Providers → Email → Enable sign ups**، لأن الحسابات تُنشأ من داخل النظام فقط.
- الرمز السري للإدارة (AUTH-004) محفوظ مُجزّأً ولا يُقرأ من أي واجهة.

## التحديثات اللاحقة

كل وحدة جديدة تضيف ملف ترحيل برقم تالٍ. على مشروع قائم يُشغَّل الملف الجديد وحده في SQL Editor بالترتيب.
